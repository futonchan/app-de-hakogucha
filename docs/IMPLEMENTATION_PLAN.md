# 実装計画と完了条件

**文書版0.4 / 実装作業はこれから。日数・工数は未見積もり。**

## 1. 段階的な実装

| 段階 | 実装するもの | 次へ進む確認 |
|---|---|---|
| 0. 準備 | 既存ファイルと指示を確認。仕様を読み、採用するPを短く宣言。新規ならTypeScript・Vite・テスト環境を作る。 | 確定値と仮値を分離した設定、型チェック・単体テストが実行できる |
| 1. 最小ループ | 10×12盤面、仮プレイヤー、十字キー、向き、開始、ゲーム時計 | 空きマスの4方向移動と画面内表示。長押し解除ができる |
| 2. 危険と箱操作 | 1秒生成、250ms落下、着地、圧死、プッシュ、パンチ、灰HP、崩れ | 再現可能な盤面で押す／壊す／逃げるを試せる。落下の単体テスト合格 |
| 3. パズル・得点 | 連結成分の消去、再落下、2秒コンボ、仮スコア | L字・同時消去・2秒境界・灰色の扱いのテスト合格 |
| 4. 1プレイ完成 | 60秒終了、生成不能、結果、再戦、ポーズ、短い説明 | 最初から最後まで遊べ、再戦で状態を持ち越さない |
| 5. ブラウザ確認 | マルチタッチ、画面リサイズ、中断、E2E、ビルド、起動README | 実行可能な試作と、実機で確認すべき項目を渡せる |
| 6. iPhone試遊 | ユーザー実機で操作・速度・視認性を確認する | 操作由来の失敗を把握し、必要な調整を提案できる |

全機能の内部基盤を先に完成させるより、段階1〜2で早めに画面と入力をつないで試す。
ただし画面だけのモックを完成したゲームとして扱わない。
各段階で小さく動かし、対応する受入テストを追加する。

## 2. 実装が返す成果物

ソースコード、package.jsonとlockfile、実行環境の記録、単体・ブラウザテスト、
実際に使えるREADMEの起動手順を作る。
仕様を補完・変更した場合はDECISIONSの記録、設定、テストを同時更新する。
原作素材を配布物へ入れず、Canvas等で描く仮素材を使う。

公開ホスティング、APIキー、DB、アカウント、アプリストア登録は不要。
完成したコードを無断で外部へ公開しない。

## 3. 実装後の標準コマンド案

これは引継ぎパックに既に存在するコマンドではない。実装時に同等のscriptsを作る。
既存プロジェクトがあれば同等コマンドでよい。

| コマンド | 目的 |
|---|---|
| `npm install` | 初回依存取得・lockfile作成。既存lockfileからの再現時は`npm ci`を使う |
| `npm run dev -- --host 0.0.0.0` | 開発用に同じLANのiPhoneから試すためのサーバー起動案 |
| `npm run typecheck` | TypeScriptの型チェック |
| `npm run lint` | 静的チェック |
| `npm run test` | 単体テストの単発実行 |
| `npm run test:e2e` | ブラウザ自動テスト |
| `npm run build` | 配布用静的ファイルの生成 |
| `npm run preview -- --host 0.0.0.0` | ビルドしたものをLAN内で確認する案 |

ポート番号・Nodeバージョン・ブラウザ依存の導入方法は、実際に構築した環境に合わせてREADMEへ記載する。
架空の起動URLや、実際には取得していないIPアドレスを書かない。
Viteのhost指定等は[参考資料W-07](../references/README.md)を参照する。

## 4. iPhoneで試すためにREADMEへ書く内容

開発PCとiPhoneを信頼できる同じLANへ接続し、PCで開発サーバーを起動する。
端末に表示される実際のNetworkアドレスをSafariで開く手順を記載する。
`localhost`はiPhone上ではiPhone自身を指すため、PCのアドレスの代わりとして案内しない。

ネットワーク分離やファイアウォールでつながらない場合の確認項目を短く示す。
OSの保護機能を一括無効化したり、ルーターの外部公開設定を求めたりしない。
LANで試せない場合は原因と別の配信案を提示し、公開を伴う場合は先に確認する。

この手順は実装後の案内内容であり、現時点で起動サーバーが存在するという意味ではない。

## 5. 試遊で記録すること

| 観点 | 記録する例 |
|---|---|
| 操作 | 1マスで止まれたか、指を滑らせた方向切替、押す／パンチの取り違え |
| 見え方 | 自分の向き、灰HP、狙った箱、落下箱を認識できたか |
| 速度 | 逃げる判断時間があったか、忙しすぎる／暇すぎる区間 |
| 失敗理由 | 判断ミス、操作ミス、視認できなかった、処理落ち、ルールが分からなかった |
| 仮ルール | 灰の連結消去、4方向プッシュ、停止中限定消去への違和感 |

まず操作領域・リピート・視認性などPの調整で改善する。
1秒生成・250ms落下・盤面サイズ・60秒等のRを変える場合は、理由と候補値を提示して確認する。
「難しそう」という推測だけでスピードを一律に下げない。
