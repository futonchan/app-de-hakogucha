# アプリでハコグチャ（仮）— MVP実装仕様書

**文書版0.4 / 2026-09-14 / 実装前の引継ぎ版**

`R-xx`は承認済み、`P-xx`は未承認の初期実装案です。
根拠と変更方法は[DECISIONS.md](DECISIONS.md)、数値は[設定資料](../config/mvp-defaults.json)を参照。
詳細を勝手に原作の確定ルールとして扱わないでください。

## 1. 目的・スコープ

iPhoneの縦持ちブラウザで、落下する箱を避け、押し、殴り、同色を揃えて消す1人用ゲームを作る。
60秒でスコアを稼ぐ。最初の検証対象は「狙ったマスに移動・停止できる」「押す／壊すを使い分けられる」
「タッチ操作が原因の理不尽な失敗が少ない」である。R-01、R-02、R-03、R-19。

入力反応を意図的に遅らせず、合意した1秒生成・250ms落下を基準に試す。
試遊の感想を理由に確定値を無断変更しない。変更提案は可能。

2人対戦、通信、CPU、ログイン、ランキング、課金、広告、ストーリー、原作画像・音源は対象外。
最終的に2人用へ発展させるため、ルール処理をUIから分離するが、通信基盤は先行実装しない。

## 2. 盤面・初期状態

| 項目 | 内容 | 区分 |
|---|---|---|
| 盤面 | 10列×12段 | R-04 |
| 座標 | 左上(0,0)、右下(9,11)。xが右、yが下 | 実装上の表現 |
| 初期箱 | なし | P-01 |
| 初期プレイヤー | (4,11)、上向き | P-01 |
| 初期スコア／コンボ | 0／0、最終連結消去時刻なし | P-07、P-08 |
| 開始演出 | 3秒カウントダウン。ゲーム時間には含めない | P-01 |
| 初回生成 | プレイ開始から1,000ms後、(抽選列,0) | P-01、R-12 |

プレイヤーに重力はかけない。箱や壁のないマスへ上下左右に移動でき、空中のマスにも留まれる。P-02。
1マスに複数箱を置かない。プレイ継続中に箱とプレイヤーを重ねない。

## 3. 移動・向き・プッシュ

入力方向を上下左右のいずれか一つとして受け取り、向きをその方向に更新する。
移動不可でも向きは変わる。斜め移動はない。R-05、P-03。

| 移動先 | 処理 |
|---|---|
| 空きマス | プレイヤーが1マス移動 |
| 盤面外 | 位置は変わらない |
| 箱あり | その箱のさらに1マス先へプッシュを試行 |

プッシュの移動先が盤面内の空きマスなら、箱だけを1マス動かし、プレイヤーはプッシュ前の位置に留まる。
空いた箱マスへ進みたい場合は、その後あらためて移動入力が必要。R-20。
押し先に別の箱がある、または盤面外なら、箱もプレイヤーも位置は変わらない。
2個以上の箱を連続して押す、引く、箱を貫通することはない。R-06、R-07、R-20、P-03。

```text
P B .   →   P . B     成功。プレイヤーは自動で進まない
P B B   →   P B B     失敗。2個同時には押せない
```

初期実装は上下左右の4方向で同じ処理を使う。ただし**上下に押せるかはP-03**。
プッシュできるのは静止している箱だけ。床にある箱、または床につながる他の箱の上に乗って支えられている箱はプッシュ可能。
落下中の箱はプッシュ不可。落下中かどうかは停止中／落下中の定義に従う。R-22。
落下中の箱にも、パンチは現在の論理マスを基準に認める。P-04。
プッシュ成功時は、現在マスから隣のマスまで250msかけて等速で表示移動し、アニメーション完了後に盤面上のグリッド座標を確定する。R-23。
箱を動かして支えがなくなった場合は、プッシュの移動完了後に支えを再評価し、落下の規則に従う。
プレイヤーがプッシュで空いたマスへ自動移動しないため、支えを失った箱の直下へ押し操作だけで入って即死する挙動を避ける。
プッシュしただけで箱のHPは変わらず、すでに受けた灰箱のダメージは残る。

## 4. パンチ・箱の種類

パンチは向いている方向の隣接1マスだけが対象。遠くの箱や近くの別方向の箱を自動選択しない。R-08。
対象が空きマス・盤面外なら空振り。方向・プレイヤー位置は変わらない。
対象が箱の場合も、パンチ操作によって変わるのは箱のHPまたは箱の有無だけであり、プレイヤー座標は変わらない。R-21。
破壊後の空きマスへ進みたい場合は、その後あらためて十字キーによる移動入力が必要。

| 種類 | 生成確率 | 初期HP | パンチの結果 |
|---|---:|---:|---|
| 赤 | 25% | 1 | 1回で破壊 |
| 青 | 25% | 1 | 1回で破壊 |
| 緑 | 25% | 1 | 1回で破壊 |
| 灰 | 25% | 3 | 3→2→1→破壊 |

R-09、R-14。灰色の残HPは数字・ヒビ等で見分けられるようにする。P-15。
パンチでHPが0になった箱はその時点で盤面から除去し、支えを再評価する。
箱の破壊によって上の箱が支えを失った場合、それらの箱は既存の落下規則どおり落下を開始する。
ただし、プレイヤーが破壊された箱のマスへ自動的に進入することはない。
パンチ破壊そのものではコンボを開始・更新せず、点も入れない。P-07、P-08。
ただし、破壊の後で別の箱が落ち、連結消去が起きた場合は通常のコンボ・加点対象となる。

## 5. 箱の生成

プレイ中に1,000msごとに1個生成する。R-12。
最上段y=0に箱がない列の一覧を作り、そこから一様に1列を抽選する。R-13。
これは「塞がれた列を再抽選する」処理と同じ分布となり、再抽選の無限ループを避けられる。

次に赤・青・緑・灰を各25%で独立に抽選する。R-14。
4個を1組にして各色を必ず1個ずつ出す方式ではない。同じ色の連続生成はあり得る。
空き列を先、色を後に抽選する順序はP-17。

最上段が全10列とも箱で塞がっている場合は、生成せず終了する。R-18。
盤面全120マスが埋まっている必要はない。判定は生成時の盤面で行う。P-11。
生成前に同時刻の入力・落下、または点滅完了済みの消去で空き列ができれば、その列を使える。消去対象が確定しただけで点滅中の場合は、ワールド時間が止まるため生成へ進まない。P-10、R-24。

初期案では、候補列からプレイヤー位置を除かない。
抽選された生成セルにプレイヤーがいた場合は圧死として終了し、生存状態の重なりを作らない。P-11。

## 6. 落下・着地・崩れ

箱は重力で下へ落ち、1マス移動する間隔は250ms。R-15。
落下時は、現在位置から次のマスまで250msかけて等速で表示移動する。ゲームロジック上のグリッド座標と描画用の表示座標は分離する。R-23。
箱は床または下の箱にぶつかると、それ以上下へ進めない。
箱の下のプレイヤーは支えではなく、落下先に入れば圧死する。R-17。

**停止中／落下中の定義（P-06、P-09）**

床y=11にある箱は支えあり。
その真下の箱が支えありなら、その上の箱も支えあり。
このように同じ列で床につながる箱を停止中とする。空白やプレイヤーは支えに含めない。
床までのつながりを失った箱は落下中となる。

箱を押す、パンチで壊す、連結消去する等で支えが失われたとき、
上に積まれた箱も生成箱と同じ250ms／マスで落ちる。R-16。
新たに支えを失った箱の最初の移動は、支え消失時刻から250ms後。P-09。
元から落下中の箱はプッシュできないため、プッシュによって次回落下時刻が先延ばしされることはない。
支えが新たにできれば停止し、再び支えを失ったらそこから250msを数える。

同時に落ちる縦積みは、下から移動可能性を計算して一括反映する。
1更新で同じ箱を2マス以上動かしたり、下の箱をすり抜けたりしない。
別の落下中の箱がまだ移動せず詰まっている場合は待ち、次の250ms後に再試行する。P-09。

## 7. 連結消去

同色の箱の連結成分を上下左右で探索し、3個以上ならその成分全体を消す。R-10。
4個・5個以上でも3個だけを選んで消さず、つながった全箱を消す。
L字・T字・四角形も、上下左右に接続していれば対象となる。

```text
RRR       R         RR         R..
          R          R         .R.
          R                    ..R
横3個     縦3個      L字3個     斜めだけ
消去       消去       消去        消去しない
```

この図は連結形状を説明するもので、各箱の下の支えは省略している。
初期案では、停止中の箱だけを判定し、落下途中の箱は探索対象から外す。P-06。
落下・プッシュの移動アニメーション中の箱は、3個以上揃った形に見える途中状態でも連結消去の対象にしない。盤面全体の判定停止ではなく、停止中で支えのある箱は従来どおり判定する。R-23。
落下箱は着地アニメーション完了後に盤面へ確定し、その後に消去判定する。プッシュも移動アニメーション完了後に盤面へ確定し、その後に消去判定する。R-23。
灰色も同じルールで消し、残HPが1・2・3でも同じ灰色として扱う。P-05。

入力による盤面変化、着地、消去・崩れなどの後に支えを再計算して判定する。
対象成分は同じ盤面スナップショットから収集し、同時に除去する。
探索順で先に一部を消して結果が変わらないようにする。
消去対象になった箱は即座に削除せず、0.5秒間点滅させてから削除する。R-24。
点滅中はゲームのワールド時間を停止し、箱の生成・落下、プレイヤー移動・パンチ・プッシュ、制限時間、コンボ判定用タイマーを進めない。描画と点滅アニメーションだけは壁時計で進める。R-24。
点滅エフェクトは箱画像に依存させず、Renderer側のopacityやオーバーレイ等で汎用的に実装する。R-24。
順序は、移動完了、論理座標確定、消去判定、点滅0.5秒、削除、支え再評価、落下開始とする。R-23、R-24。
除去後は支えを更新するが、次の250msを飛ばして箱を底まで一瞬で落とさない。

## 8. コンボ・スコア

最初の連結消去をコンボ1とし、以後の連結消去について次の式で更新する。R-11、P-07。

```text
直前の連結消去があり、今回時刻 − 直前時刻 <= 2,000ms:
    combo = 前回combo + 1
それ以外:
    combo = 1
直前の連結消去時刻 = 今回時刻
```

2,000msちょうどは継続、2,001msは新規コンボとなる。
消去なしで2,000msを超えたら現在のコンボ表示を0に戻す。最大コンボは保持する。
同じ時刻で赤3箱と青3箱が消えても、コンボは1回だけ増える。
同時刻内の複数の処理段階で連結消去が起きた場合も、1消去イベントへまとめる。P-07。
パンチ破壊で2秒の期限を延長しない。

スコアは仮式である。P-08。

```text
消去イベントの点数 = 消えた箱数 × 100 × [1 + 0.5 × (combo − 1)]
パンチ破壊の点数 = 0
```

例：コンボ1で3箱消去は300点、続くコンボ2で4箱消去は600点、合計900点。
同時に2グループ・計6箱が初回消去なら600点、コンボ1。
コンボ倍率の上限や色別得点差は初期案では設けない。

## 9. 終了・ポーズ・リトライ

| 条件 | 結果表示 | 規則 |
|---|---|---|
| ゲーム時間60,000ms到達 | タイムアップ | R-03、P-14 |
| 落下箱がプレイヤーのマスに入る | 箱に潰された | R-17 |
| 生成時に上端の空き列がない | これ以上箱を生成できない | R-18、P-11 |
| 生成セルにプレイヤーがいた | 箱に潰された | P-11 |

時間切れ時刻では箱生成・移動・パンチ・消去得点を追加しない。P-14。
圧死した落下の後で同色が揃っても、その消去で死亡を取り消さない。P-10。
ただし同時刻の入力で先に危険を除去・回避できた場合は生存できる。

ポーズは制限時間・生成・落下・コンボ期限・入力リピートを全て凍結する。P-13。
連結消去の点滅中も同様にワールド時間を凍結するが、プレイヤーが任意で解除するポーズではなく、0.5秒後に自動で再開する。R-24。
画面非表示やフォーカス喪失、横持ちへの変更で入力を全解放し、自動ポーズする。
画面を戻しただけで勝手に再開せず、「再開」を押してから続ける。

リトライは新しいゲーム状態・seed・初期箱・初期位置・スコア・コンボ・時計へ戻す。
前ゲームの落下予約、押しっぱなし、ポーズ理由、結果を持ち越さない。P-01、P-13、P-17。

## 10. iPhone画面・操作

縦持ち画面の上にスコア／時間／コンボ、その下に10×12盤面、下側に操作領域を配置する。R-02、P-15。
左親指で十字キー、右親指でパンチ。同時入力を受け付ける。
プレイヤーは向きが分かる仮アイコン、パンチ対象は隣接枠などで示す。
色だけでなく、赤・青・緑・灰を識別する文字や簡単な記号も併用する案とする。

十字キーの初期値：押下直後に1操作、250ms待ってから100msごとに1操作。P-12。
押下中に指を滑らせて別方向へ切り替えられる。斜め部分では1方向に確定するか無入力とし、
2方向を同時に移動させない。詳しい優先規則は入力実装に記録する。
パンチは押下時に1発だけ。長押しで灰箱が自動的に3回殴られない。

初期UI目標は方向ボタンの押下領域56 CSS px程度、最低48 CSS pxを目安とする。P-15。
これはこのプロジェクトの仮目標であり、iPhoneの規格値の主張ではない。
画面の小さい場合は盤面を縮め、操作領域を優先する。盤面マスは正方形を保つ。
ホームインジケータ、アドレスバー等と重ならないように実機で確認する。

「縦持ち固定」は縦向き前提のレイアウトとして実現する。
端末を物理的に回転できなくする意味ではない。横向きではポーズして縦持ちを案内する。P-13。
特定ブラウザの画面向きロック機能に必須依存しない。

## 11. 実装・検証の境界

ゲーム実行時のネットワーク通信、APIキー、サーバー、DBは不要な構成とする。P-16。
開発用依存ライブラリの取得と、完成した静的ファイルの配信は別の話として扱う。
オフライン起動の保証、ホーム画面追加、アプリストア配布は今回の受入条件に含めない。

描画60fpsを目標にするが、検証なしに保証しない。時間進行や衝突結果をフレーム数で決めない。
実装完了には自動テストとブラウザ試験を行う。iPhone実機の操作感は人間が別途確認する。
詳細は[受入テスト](ACCEPTANCE_TESTS.md)と[実装計画](IMPLEMENTATION_PLAN.md)。
