# 受入テスト仕様

**文書版0.4 / 以下は実装すべきテスト条件であり、実行済みの結果ではありません。**

確定要件は`R-xx`、未承認の初期実装案は`P-xx`として追跡する。
仮仕様を変えた場合は対応するテストも更新するが、確定要件をテスト都合で変更しない。
実行結果は別途記録し、未実施を合格にしない。

## 1. テストの前提

座標は左上(0,0)、右下(9,11)。R=赤、B=青、G=緑、A=灰、P=プレイヤー。
時刻はカウントダウン後のゲーム時刻ms。
単体テストでは初期盤面・箱HP・落下期限・seed・入力時刻を直接組み立ててよい。
生成・衝突などを切り分けるfixtureはテスト内だけに置き、通常プレイのルールを弱めない。

盤面の連結だけを調べるテストと、重力も含めるテストを区別する。
停止中のみを消すP-06のテストでは、対象箱が床または他の箱で支えられている状態を作る。
箱一覧の並び順を逆にしたfixtureでも、落下・消去・得点の結果を比較する。

## 11. 共通の不変条件と完了判定

coreの各更新後に、開発・テスト環境で次を確認する。

- 全箱と生存プレイヤーの座標が盤面内。箱IDと占有セルは一意。
- 生存中に箱とプレイヤーが同じセルを占有しない。
- 赤青緑の残HPは1、灰の残HPは1〜3。HP0の箱は残さない。
- 支えありの箱は落下期限なし。支えなしの箱には将来の期限がある。
- ゲーム時刻は単調増加し、ポーズ中は不変。得点は非負整数。
- 除去済み箱や終了済みゲームへ予約イベントを再適用しない。

Rに関する自動テストが合格し、実装したPのテストも合格していることを実装側の完了条件にする。
ブラウザ試験やiPhone実機試験が未実施なら、その範囲を未完了として報告する。
「全テスト合格」「iPhoneで動作確認済み」は、対応する実行記録がある場合だけ使う。
